# HH Analytics: Анализ рынка вакансий аналитиков

## 🧹 Релиз от 16.07.2026 — Система очистки данных и привязка к регионам

### Проблема

При ежедневном сборе вакансий через HeadHunter API часть записей оказывается нерелевантной: рекрутеры при публикации выбирают неверную профессиональную роль (например, «Аналитик» для водителя погрузчика, повара или менеджера по продажам). Это искажает аналитику и требует ручной очистки.

### Что сделано?

1. **Разработан ансамблевый классификатор вакансий (v5)**
   
   Пять методов, работающих в связке с весовыми коэффициентами:
   
   | Метод | Вес | Логика |
   |-------|-----|--------|
   | Стоп-слова | право вето | Явный мусор: «бульдозер», «повар», «курьер», «продуктолог» |
   | Маркеры аналитики | 0.9 | Ключевые слова: «аналитик», «SQL», «дашборд», «Python», «данные» |
   | N-граммы с ролью | 0.3 | Сравнение названия вакансии с эталонной ролью через триграммы |
   | N-граммы с ключевыми словами | 0.6 | Сравнение с расширенным словарём роли (среднее топ-3 совпадений) |
   | Правила | 0.7 | Регулярные выражения: позитивные и негативные паттерны |
   
   **Результат классификации на 8 145 вакансиях:**
   - ✅ **6 235** — достоверные (OK)
   - ❌ **1 910** — мусор (FAKE)

2. **Автоматизирована ежедневная очистка**
   
   - Новый скрипт `clean_vacancies.py` запускается через 10 минут после сбора вакансий (21:10 MSK)
   - Все новые вакансии получают метку `is_fake` (TRUE/FALSE) и причину классификации
   - Скрипт обрабатывает только непроверенные записи, не трогая уже размеченные

3. **Привязка вакансий к регионам РФ**
   
   - Загружены полигоны 85 субъектов РФ в таблицу `regions`
   - Для каждой вакансии определён регион по координатам (`region_id` через PostGIS)
   - Настроен триггер для автоматической привязки новых записей
   - Вакансии за пределами РФ остаются с `region_id = NULL` (Кипр, США, Сербия и др.)
   - В дашборд добавлена **карта регионов** с медианной зарплатой по субъектам РФ (при наличии >3 вакансий в регионе) и кластеризованными геоточками вакансий с разбивкой по IT-аккредитации работодателя

### Интеграция с дашбордом

- В DataLens добавлен **единый JS-селектор «Чистый режим»** — переключатель, применяющий фильтр `is_fake = FALSE` ко всем кастомным JS-чартам дашборда
- Стандартизирован код всех 12 чартов: единый подход к фильтрации, парсингу дат и параметрам
- Пользователь может в один клик переключиться между полной и очищенной выборкой
- **Исключения:** фильтр не применяется к карте (стандартный чарт DataLens, параметр не передаётся) и к вкладке «Таблица» (пользователь сам определяет структуру и видит нерелевантные вакансии по названию и роли)

## 📊 vacancy_snapshots: измерение состояния рынка труда (22/06/2026)

Введена таблица `vacancy_snapshots` - ежедневный снимок активного рынка вакансий. В отличие от `vacancies`, которая фиксирует факт появления вакансии (архив событий), `vacancy_snapshots` фиксирует состояние рынка на конкретную дату.

Это позволяет рассчитывать метрики, недоступные при анализе только новых публикаций:
- **Demand** - относительный объём активных вакансий (`active_today / avg(active_last_30_days)`)
- **Market Turnover** - скорость движения рынка (`(new + closed) / active`)
- **Vacancy Lifetime** - средняя продолжительность жизни вакансии
- **Salary Pressure** - изменение медианной зарплаты среди активных вакансий

На их основе строится композитный **Job Market Health Index**, отражающий текущее состояние рынка труда аналитиков в России. При накоплении данных за 60+ дней в дашборд будет добавлена комплекснаяметрика здоровья рынка, поскольку текущая версия методологически некорректна.

### Логика работы `snapshot_daily.py`

Скрипт ежедневно фиксирует состояние активного рынка вакансий аналитиков на hh.ru. Для обеспечения полноты данных реализована адаптивная стратегия сбора:

1. **Быстрый режим**  
   Выполняется запрос по всей России (`area=113`) без фильтрации по дате. Если API возвращает менее 2000 вакансий - сбор завершается, так как лимит не достигнут.

2. **Полный режим**  
   При обнаружении ровно 2000 вакансий (максимум для одного запроса без разбивки) скрипт автоматически переключается на разбивку по регионам:  
   - Загружается актуальный список регионов из `/areas/113`  
   - По каждому региону выполняются пагинированные запросы (до 20 страниц)  
   - Результаты объединяются с удалением дубликатов

3. **Обогащение и сохранение**  
   - Для каждой найденной вакансии запрашивается рассчитанная зарплата из таблицы `vacancies`  
   - Формируется запись `(vacancy_id, snapshot_date, salary_avg_rub, salary_avg_net_rub)`  
   - Данные сохраняются через `upsert` с уникальным ограничением `(vacancy_id, snapshot_date)`, что гарантирует идемпотентность при повторных запусках

Скрипт устойчив к временным ошибкам API (403, 429, таймауты) за счёт встроенного механизма повторных попыток и пауз между запросами.

## Логика пересчёта зарплат (триггеры PostgreSQL)

### 1. Перевод в рубли

- Если валюта RUR - значения копируются без изменений
- Для других валют:
  - Маппинг: BYR (из HH) → BYN (в таблице курсов)
  - Поиск курса на дату публикации вакансии (ближайший предыдущий)
  - Если курс на дату отсутствует - берётся последний известный
  - salary_in_rub = salary_in_currency × rate_to_rub

### 2. Расчёт чистой зарплаты (прогрессивная шкала НДФЛ)

Шкала налогообложения с 2025 года:

| Годовой доход | Ставка |
|---------------|--------|
| до 2,4 млн руб. | 13% |
| 2,4–5 млн руб. | 15% на превышение |
| 5–20 млн руб. | 18% на превышение |
| 20–50 млн руб. | 20% на превышение |
| более 50 млн руб. | 22% на превышение |

Принцип расчёта:
- Годовой доход = месячная зарплата × 12
- Налог рассчитывается прогрессивно по диапазонам
- Месячный налог = годовой налог / 12
- Чистая зарплата = гросс зарплата − месячный налог

### 3. Средние значения

- salary_avg_rub = (salary_from_rub + salary_to_rub) / 2
- salary_avg_net_rub = (salary_from_net_rub + salary_to_net_rub) / 2
- Если одно из значений NULL - результат NULL

## Процессы сбора данных

### Ежедневный сбор курсов валют (daily_currency.py)
- Запуск: 04:00 UTC (07:00 MSK)
- Источник: ЦБ РФ
- Действие: получение курсов за текущий день → upsert в exchange_rates

### Ежедневный сбор новых вакансий (daily_vacancies.py)
- Запуск: 18:00 UTC (21:00 MSK)
- Период: вчера и сегодня
- Логика:
  1. Сбор ID вакансий за период
  2. Фильтрация ID, отсутствующих в базе
  3. Загрузка полных данных по новым ID
  4. Пакетная вставка в vacancies (по 50 строк)
- Защита от дубликатов: проверка существующих ID перед вставкой

### Ежедневный снимок рынка (snapshot_daily.py)
- Запуск: после основного сбора
- Логика:
  1. Запрос всех активных вакансий аналитиков с зарплатой
  2. При достижении лимита 2000 - переключение на разбивку по регионам
  3. Получение зарплат из `vacancies`
  4. Upsert в `vacancy_snapshots` с уникальным ограничением `(vacancy_id, snapshot_date)`

### Исторический сбор вакансий (vacancies_historical.py)
- Запуск: вручную из GitHub Actions
- Параметры: количество дней (по умолчанию 30)
- Логика: аналогична ежедневному сбору, но за указанный период
